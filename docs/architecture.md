# 구조와 설계

```text
cmd/miniredis → config (설정·조립)
HTTP 요청 → internal/httpapi → internal/store → internal/hashtable
cmd/aofrepair → internal/store (오프라인 복구)
internal/demo (HTTP 캐시 연동 통합 테스트)
```

해시 테이블은 입력·HTTP·TTL 판단을 모르며 키 비교·노드 보관만 담당합니다. Store가 검증·시계·만료·용량·기록 순서를 관리하고 HTTP 계층이 경로·JSON·인증·오류 코드를 변환합니다.

## 해시 테이블

FNV-1a 64비트는 UTF-8 바이트마다 XOR 후 곱셈합니다. 버킷 인덱스는 해시값을 버킷 수로 나눈 나머지입니다. 충돌은 연결 체이닝으로 처리하고 해시와 원래 키를 모두 비교합니다. 최초 16버킷이며 새 키 삽입으로 적재율 0.75를 넘으면 2배로 일괄 재배치합니다. 삭제 후 축소하지 않습니다.

평균 저장·조회·삭제는 O(1), 한 체인에 몰리면 O(n), 확장은 O(n)입니다. FNV는 암호학적 해시가 아니며 악의적인 충돌 공격 방어를 보장하지 않습니다. 공개 접속은 인증과 프록시 요청 제한이 필요합니다. 버킷 수와 저장 가능한 키 수는 같지 않습니다.

## 동시성과 기록 순서

Store의 `mu`는 모든 테이블 접근·만료 삭제·데이터 사용량을 보호합니다. 조회도 만료 노드를 삭제할 수 있어 단일 Mutex를 사용합니다. `writeMu`는 변경·AOF 기록·교체·종료·능동 만료 정리의 순서를 맞춥니다. 디스크 I/O 동안 메모리 잠금을 잡지 않습니다.

영속성 변경은 게이트를 획득한 작업 하나만 고루틴으로 실행합니다. 호출자는 실행 전 대기부터 기본 3초까지만 기다리지만 실행된 디스크 호출은 취소되지 않습니다. 작업은 호출자가 떠난 뒤에도 게이트를 유지하여 순서를 보장합니다. panic은 스택과 함께 기록하고 추가 변경을 거부합니다. 이미 시작한 변경은 결과 불명일 수 있습니다.

## 만료·용량

Store 생성은 만료 정리 고루틴을 시작하므로 직접 생성하는 Go 호출자는 `Close()`로 정리해야 합니다.

엔트리는 문자열 값과 만료 시각입니다. 0 시각은 무기한, `now >= expiresAt`은 만료입니다. 시계 인터페이스는 테스트에서 가상 시간을 주입합니다. 실행 중에는 가능한 단조 시계 정보를 유지하고 AOF에는 벽시계 절대 만료를 저장합니다.

조회 시 지연 삭제하고, 메모리·AOF 모드 모두 약 100ms마다 적응형 능동 정리를 수행합니다. 256 탐색 단위씩 잠금을 나누며 기본 탐색량을 테이블 크기에 비례시킵니다(대략 1초에 한 순회를 목표). 방문 노드의 25% 이상을 삭제하면 같은 tick에서 더 진행하되 약 25ms의 작업 예산을 배치 사이에 확인합니다. 게이트 획득을 한 번 실패하면 다음 시도 대기를 1ms에서 5ms로 늘리고 성공 후 되돌립니다. 배치 내부·충돌 체인·스케줄링까지 엄격한 25ms 상한을 보장하지는 않습니다. 약한 순회는 확장 시 다시 시작하며 새 노드는 다음 순회에서 처리될 수 있습니다. 오래된 커서가 본 노드는 실제 테이블에서 다시 확인해 새 값을 잘못 지우지 않습니다. 탐색 단위는 빈 버킷·노드 방문을 세지만 키 재확인·삭제의 충돌 체인 탐색까지 상수 시간으로 보장하지는 않습니다. 부하·키 수에 따라 회수 지연이 늘 수 있습니다.

데이터 사용량은 키 바이트+값 바이트+항목당 64바이트로 근사합니다. 기본 상한 256 MiB이며 증가분이 상한을 넘는 SET은 AOF append 전에 거부합니다. 같은 크기·더 작은 갱신과 삭제는 허용합니다. 증가하는 SET이 상한에 걸리면 이미 획득한 변경 게이트 아래에서 최대 4,096 탐색 단위의 동기 만료 회수를 먼저 시도하고, old/found/delta를 다시 계산합니다. 회수된 키에 다시 SET할 때는 새 삭제 예약을 확보합니다. 제한된 탐색이 만료 키를 모두 찾는 것은 아니므로 여전히 상한 거부가 가능하며 회수 비용도 해당 요청에 포함됩니다. replay가 더 작은 새 상한을 초과하면 데이터는 보존해 기동하고 경고하며 증가하는 변경을 거부합니다. 상한을 0으로 해제할 수 없습니다. 버킷·할당기·재작성·GC 등은 이 상한에 포함되지 않습니다.

AOF 삭제 예약은 능동 정리 시 변경 게이트 아래에서 회수합니다. GET의 지연 삭제는 동시 SET과의 예약 경합을 피하려고 예약을 직접 줄이지 않습니다. 재작성 시 만료 노드를 물리적으로 제거한 뒤 예약을 다시 계산합니다. 단순히 만료 노드를 예약 합계에서만 빼면 같은 노드의 후속 갱신이 삭제 공간을 확보하지 못하므로 그렇게 하지 않습니다.

LRU/LFU·패턴 삭제·샤딩·복제는 구현하지 않습니다. 일괄 확장과 스냅샷은 지연·임시 메모리 비용이 남습니다. 성능은 별도 측정이 필요합니다.


## 헬스 관찰

journal의 fatal·closed 여부, 가장 오래된 미동기화 시점, 실행 중인 Write 시작 시점은 atomic 상태로 게시합니다. `/health`는 metadata 잠금을 획득하지 않으므로 정상 쓰기의 잠금 경합을 장애로 판단하지 않습니다. 미동기화 또는 실행 중 Write가 `MaxUnsyncedAge`(기본 3초)를 넘거나 fatal·종료·작업 panic이면 비정상입니다. 경과 시간은 단조 시계 기준이므로 벽시계 조정에 영향을 받지 않습니다. 재작성 전체 지연이나 데이터 용량을 모두 판정하는 지표는 아닙니다.
