# 외부 앱에서 캐시로 사용하기

별도 소비 앱 없이 HTTP 클라이언트가 다음 흐름을 구현하면 됩니다.

1. `GET /keys/product%3A42`가 200이면 저장된 응답을 사용합니다.
2. 404면 원본 DB·API에서 조회합니다.
3. 원본 응답을 문자열로 직렬화해 `PUT /keys/product%3A42`에 TTL과 함께 저장합니다.
4. 원본을 변경한 테스트·사용자는 `DELETE /keys/product%3A42`로 무효화합니다.

네트워크 오류나 503은 정상 미적중 404와 다릅니다. 원본으로 우회할지, 실패할지는 앱에서 결정하세요. 결과 불명인 쓰기를 무조건 재시도하면 TTL이 다시 시작할 수 있습니다. 토큰이 설정되어 있으면 키 API마다 Bearer 헤더를 보냅니다.

원본 조회와 저장 사이에 다른 요청이 무효화하면 오래된 값이 다시 저장될 수 있습니다. TTL만으로 이 경합을 완전히 해결하지는 못합니다. 강한 최신성이 필요한 앱은 버전·별도 동기화 등을 설계해야 합니다. 미적중 동시 요청을 합치는 기능도 제공하지 않아 원본에 요청이 몰릴 수 있습니다.

`internal/demo/demo_test.go`는 원본·저장소·소비자를 같은 테스트 안의 httptest 서버로 띄워 HTTP 캐싱, 무효화, TTL과 우회를 검증합니다. 이것은 기능 검증이며 성능 비교 결과가 아닙니다. 성능 비교에는 동일한 원본·부하·연결 재사용·캐시 준비 조건, 디버그 OFF와 AOF on/off 구분이 필요합니다. Postman 단건 지연만으로 처리량·꼬리 지연 성능을 단정하지 마세요.
