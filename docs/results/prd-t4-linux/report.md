## 조건

## 자동 점검

- 측정기(원본 모형 포함)가 전체 4코어의 절반 넘게 쓴 조건: warm/100ms/동시 20/ON (AOF off)(2.08코어). 이 조건의 처리량은 mini-Redis가 아니라 측정기와 CPU 경합이 한계일 수 있으니, 서버의 최대 처리량으로 인용하지 마세요.

## 미리 적어 둔 예상치

- **원본 0ms, 웜 캐시**: ON과 OFF 모두 HTTP 왕복 한 번입니다. ON은 인증 검사와 저장값 JSON 한 겹을 더 풀어야 하므로 **비슷하거나 ON이 약간 느린 것이 정상**입니다. 이 조건에서 ON이 크게 빠르면 측정을 의심하세요.
- **원본 0ms, 빈 캐시**: ON의 미스는 캐시 조회 → 원본 → 캐시 저장으로 왕복이 세 번이라 **ON이 OFF보다 느립니다.**
- **원본 100ms, 웜 캐시**: OFF의 p50은 100ms보다 조금 크고, 처리량 상한은 동시 수 × 1000/100 req/s입니다(동시 1이면 약 10, 동시 20이면 약 200). ON은 원본을 부르지 않으므로 p50이 1ms 안팎이고 처리량은 mini-Redis와 이 기기의 CPU가 결정합니다. 이 배수는 **인위적인 100ms 대기를 건너뛴 효과**이지 mini-Redis가 일반적으로 그만큼 빠르다는 뜻이 아닙니다.
- **원본 100ms, 빈 캐시**: ON의 미스는 OFF보다 캐시 왕복 두 번만큼 느립니다. 스탬피드에서는 동시 1이면 키당 원본 호출이 1이지만, 동시 요청이 겹치면 1보다 커집니다(동시 미스를 합치는 기능이 없기 때문).

## 해석할 때의 한계

- **같은 기기·루프백 측정입니다.** 측정 CLI, 원본 모형, mini-Redis가 한 기기의 CPU를 나눠 쓰고 네트워크는 루프백입니다. 실제 배포에서는 캐시 왕복에 네트워크 지연이 더해지므로 ON의 이득은 이 결과보다 작아지고, 0ms 조건에서 ON의 손해는 커집니다.
- **측정기도 부하입니다.** 원본 모형이 측정기 프로세스 안에 있어 측정기의 CPU 사용과 GC가 OFF·ON 양쪽에 영향을 줍니다. 표의 "측정기 CPU 코어"가 전체 코어의 절반을 넘는 조건의 처리량은 서버가 아니라 측정기의 한계일 수 있습니다. 지연 표본은 고정 크기 히스토그램에 기록하므로 표본 기록 때문에 메모리가 늘지는 않습니다(HTTP 요청과 JSON 처리의 할당은 그대로 있습니다). 백분위수의 상대 오차는 0.4% 이하입니다.
- **원본 지연은 인위적입니다.** 원본은 `time.Sleep`으로 DB·외부 API 비용을 흉내 낼 뿐, 실제 DB처럼 부하에 따라 느려지지 않습니다.
- **균등 분포·상품 100개의 웜 캐시는 적중률 100%인 최선의 경우입니다.** 키 수가 캐시보다 많거나 인기 편중·TTL 만료·무효화가 있으면 적중률이 내려갑니다.
- **AOF 수치는 "관측한 비용"입니다.** 웜 캐시는 거의 GET만 하므로 AOF 차이가 나와도 AOF 비용이 아닙니다. 빈 캐시·스탬피드는 측정 구간이 짧아 1초 주기 Sync를 포함하지 못할 수 있습니다(표의 측정 시간 참고). AOF 비용은 지속 쓰기 시나리오에서 보되, 이 값도 "쓰기 응답이 돌아올 때까지의 지연"이지 "디스크 동기화가 끝날 때까지의 지연"이 아닙니다. "추정 Sync 주기"는 측정 구간의 초 수일 뿐 Sync가 그만큼 실행·완료됐다는 증거가 아니며, 재작성은 AOF 파일이 교체되거나 줄어든 것을 50ms 간격으로 관찰해 셉니다.
- **동시 요청 수를 고정한 닫힌 루프 측정입니다.** 처리량은 "이 동시성에서 얻은 처리량"이며, 특정 요청률을 견디는지 보는 부하 시험과 다릅니다. 서버가 느려지면 요청도 덜 보내므로 꼬리 지연이 실제보다 작게 보일 수 있습니다.
- **적중·미스는 클라이언트가 센 값입니다.** mini-Redis는 통계 API가 없으므로 GET 응답 200을 적중, 404를 미스로 셉니다.
- **서버 CPU·메모리는 프로세스 전체 수명 기준입니다.** 실행마다 서버를 새로 띄우므로 시작, 미리 채우기, 측정, 정리가 모두 포함됩니다. 측정기 CPU는 측정 구간만 잽니다.
- 실패한 요청(오류·타임아웃·검증 실패)은 지연·처리량에서 빼고 따로 셉니다. 실패가 0이 아니면 그 조건의 속도 수치는 비교에 쓰지 마세요.
